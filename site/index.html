Graphviz dot,
in pure Go.

gogv is a Go implementation of the Graphviz dot program, following Graphviz 16.1.0. It lays out graphs written in the DOT language and writes them as SVG and in the other output formats of dot. It needs no cgo, no embedded WebAssembly and no installed Graphviz.

Install v0.3.0 Try it in the browser Source on GitHub

Three ways to run it

Go library

gogv.Render writes the bytes that dot -T<format> writes, and returns the warnings and a *gogv.SyntaxError with its line. It is safe for concurrent use.

out, warnings, err := gogv.Render(ctx, src, "svg")

Command line

A dot that accepts -T<format>, -o<file>, -V and -Kdot, and rejects the other flags of Graphviz's dot with exit status 1 instead of ignoring them.

dot -Tsvg graph.gv -o graph.svg

WebAssembly module

The library starts no process and reads no file, environment variable or network, so it builds and runs in WebAssembly. The playground on this page runs it.

GOOS=js GOARCH=wasm go build ./...

Playground

Edit the DOT source, and gogv v0.3.0 lays it out in this page with WebAssembly. No server is involved.

A feature that is not supported yet gives a warning, as the command line writes it, and the graph is drawn with the default that the warning names.

    With go tool pprof

    go tool pprof draws its call graphs with dot: -svg, -web and the Graph view of -http. With gogv installed as dot, they work without Graphviz: nodes are filled with their colors, hot edges are thicker and kept straight, residual edges are dotted, tag nodes are boxes with depth, and the Graph view selects nodes by their id.

    go install github.com/ekalinin/gogv/cmd/dot@v0.3.0
export PATH="$(go env GOPATH)/bin:$PATH"
go tool pprof -http=:8080 cpu.prof

    Output formats

    • canon
    • plain
    • plain-ext
    • svg
    • svg_inline
    • dot
    • gv
    • xdot
    • xdot1.2
    • xdot1.4
    • json
    • json0
    • dot_json
    • xdot_json

    The layout is the layered layout of dot: ranking, crossing minimization, positioning, and spline or polyline routing, with clusters, edge labels, table labels and node ports. The Status and "Not supported yet" lists of the README name the attributes and values that gogv supports. A feature that is not supported yet gives a warning that names the default used instead.

    Install

    With Go 1.26 or later, install the dot command line of v0.3.0:

    go install github.com/ekalinin/gogv/cmd/dot@v0.3.0
dot -V   # dot - graphviz version 16.1.0 (gogv 0.3.0)

    The command is named dot, as Graphviz's is: when Graphviz is installed too, the dot found first in PATH runs, and dot -V tells them apart. Add the library to a module with:

    go get github.com/ekalinin/gogv@v0.3.0

    Releases have no prebuilt binaries.

    Conformance

    make conformance compares v0.3.0 with Graphviz 16.1.0 built without Pango on 587 cases: canon byte for byte, plain by nodes, edges and size, svg by size and the structural similarity of the rasterized documents, and dot, xdot and JSON by their objects, attributes and drawing operations.

    • 516 cases pass
    • 32 cases are known differences (testdata/conformance/known-differences.yaml)
    • 39 cases use features that are not supported yet
    • 0 cases fail

    The conformance report lists the cases by capability and by format.

    Clean-room implementation

    gogv is written from published papers, the Graphviz documentation and the observed behavior of Graphviz 16.1.0, used as a black box. It contains no code from Graphviz or from its ports and bindings. Every Go file names its sources in Provenance: lines:

    • Gansner, Koutsofios, North and Vo, "A Technique for Drawing Directed Graphs" (IEEE TSE, 1993): ranking, crossing minimization, positioning
    • Dobkin, Gansner, Koutsofios and North, "Implementing a General-Purpose Edge Router" (Graph Drawing 1997): edge routing
    • the Graphviz documentation
    • outputs of Graphviz 16.1.0 for chosen inputs

    Text is measured with tables generated from the Liberation 2.1.5 fonts, and elementary functions come from a port of fdlibm, so that the output is the same, byte for byte, on every platform.
