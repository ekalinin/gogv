# Design

## Context

See proposal.md - Why. Today the Graphviz version is written in two places of the shipped code: `const GraphvizVersion = "16.1.0"` in `internal/cli`, which `-V` prints, and the literal `<!-- Generated by graphviz version 16.1.0 (gogv)` in `internal/output/svg.go`. The root package imports `internal/output`, and `internal/cli` imports the root package. The cli spec pins the `-V` line, the output-formats spec and the tests only the start of the SVG comment, and `internal/cli`'s test checks the line against the patterns with which gopuml reads a Graphviz version. The other mentions of 16.1.0 (`internal/conformance`, `tools/provenance`) name the reference of the conformance harness, not what gogv writes.

gopuml's `switch-to-gogv` (design D4) writes `dot - graphviz version ` + `gogv.GraphvizVersion` + ` (gogv ` + the module version from its build info + `)`, and requires a tag of gogv that exports the constant.

## Goals / Non-Goals

**Goals:**

- One place for the Graphviz version that gogv writes, exported for other Go programs
- A tag that gopuml can require

**Non-Goals:**

- gogv's own module version as an API: gopuml reads it from its build info
- The layout fixes for gopuml's 12 differing cases (its D9), which come in later tags
- The version that the conformance harness and `tools/provenance` name for the reference

## Decisions

### D1. The constant lives in internal/output, the package re-exports it

`internal/output` defines `const GraphvizVersion = "16.1.0"` and builds the SVG comment from it. The root package declares `const GraphvizVersion = output.GraphvizVersion`, with a doc comment that names `dot -V` and the SVG comment, and `internal/cli` prints `gogv.GraphvizVersion`; its own constant goes, as `internal/cli` is not importable.

Alternative: the constant in the root package, which `internal/output` cannot import (the root package imports it).
Alternative: a new internal package for one constant, one more package for what `internal/output` already writes.

### D2. Release as v0.2.0

The constant is new API, so the next version is a minor one, v0.2.0. Its notes, `docs/releases/v0.2.0.md`, are part of this change's pull request, as the README's Releasing section allows; after the merge and a passing CI, `make release VERSION=v0.2.0` tags the merge commit.

Alternative: v0.1.1, which reads as a fix release.

## Risks / Trade-offs

- [The literal of the SVG comment and the constant stop matching] → the comment is built from the constant, and the test of the scenario reads all three places
- [The output changes by mistake] → the `make determinism` hash of all outputs must stay `0915e7dbdad0afba7d0d868f4ffd30de6085772be21fcbbce57d67fdabcb23bc`, and `make conformance` must leave `conformance-report.md` unchanged
